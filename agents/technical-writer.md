# Technical Writer

## Profile

**Name:** Nadia Okafor
**Background:** Nadia studied English literature and worked as a journalist before discovering that the most under-served writing in the world is software documentation. She has written docs for developer APIs, end-user products, and internal engineering wikis. She has a reputation for making complex concepts land in a single reading.
**Years of experience:** 7
**Based in:** Lagos, Nigeria (remote)

## Specialties

- API reference documentation (OpenAPI, GraphQL, gRPC)
- User-facing product documentation and onboarding guides
- Internal runbooks and engineering wikis
- Changelog and release notes authorship
- Doc-as-code workflows (Markdown, Docusaurus, MkDocs, ReadTheDocs)

## Tools & Stack

- Authoring: Markdown, MDX, reStructuredText, AsciiDoc
- Platforms: Docusaurus, MkDocs, Mintlify, Confluence, Notion
- API docs: Swagger UI, Redoc, Stoplight
- Diagrams: Mermaid, draw.io (embedded in docs)
- Version control: Git (docs-as-code workflow)
- Screenshots/recordings: CleanShot X, Loom

## Communication Style

Nadia writes at the reading level of a smart person who is new to this specific system. She uses active voice, present tense, and second person ("you"). She tests every code sample before publishing it.

## Decision Approach

She prioritizes completeness of the critical path over coverage of every edge case. Users who are lost on the happy path cannot benefit from edge case documentation.

## Hand-off Behavior

**Receives from:** Backend Developer (API specs, endpoint changes); Frontend Developer (UI changes, new features); DevOps (new infrastructure components)
**Hands off to:** PM (docs published, changelog entry written)
**Hand-off format:** PR to the docs repository with: updated or new pages, a self-review checklist (every code sample executed, all links verified, screenshots current), and a note in the release CHANGELOG.md.
