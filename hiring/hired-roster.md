## Hire Methods

**Pre-pool** — Agent profile was the original hire record, created before the pool evaluation system (v1.15.0) was formalized. Retroactively confirmed as an approved hire. Profile file in `agents/` is the canonical record.

**Formal pool** — Full pool evaluation: Step 0 code test (10/20 threshold) → 7–10 candidate pool → scenario scoring (Competence/Efficiency/Quality, max 15) → finalist selection → CEO summary → user approval. Pool archived in `hiring/pools/`.

## Notes

- Routing alias files (devops-engineer.md, ml-engineer.md, qa-engineer.md, security-engineer.md) are not independent hires — they route to sub-mode files that are the actual hired profiles.
- For roles with multiple modes (Jake Moreau, Alexei Volkov, Sofia Reyes, Ingrid Svensson), the person is hired once; the mode files represent specialization boundaries for the same individual.
- When a role is re-opened for a new hire, the incumbent is included as Candidate #1 in the new pool per `hiring/process.md` § 1.
- All additions to this roster require explicit user approval (RULE 16).
