# Hiring Pool Archives

Every confirmed hire — and every evaluated proposal that did not result in a hire — gets a pool file in this directory.

## Naming Convention

`{role-slug}.md` — matches the agent file name without the `.md`, e.g.:
- `audio-streaming-engineer.md` → `hiring/pools/audio-streaming-engineer.md`
- `backend-developer.md` → `hiring/pools/backend-developer.md`

## What Each Pool File Contains

1. Pool table (7–10 candidates, global distribution, one strength and one trade-off each)
2. Scenario used (name + full text from `hiring/scenario-bank.md`)
3. Per-candidate scenario response (2–4 sentences) and scores (Competence / Efficiency / Quality / Total)
4. Scoring summary table (all candidates ranked)
5. Selection decision (Finalist, Runner-up, rationale)
6. Outcome (hired / not hired + reason)

## When a Role is Opened Again

If the same role is opened for a second hire, create a new pool file with a date suffix:
`audio-streaming-engineer-2026-08.md`

The prior pool is referenced but not modified.

## Retroactive Pools

Some early hires were made before this system existed. Their pools are retroactively reconstructed for the record. These are marked `[RETROACTIVE]` in the pool file header.
